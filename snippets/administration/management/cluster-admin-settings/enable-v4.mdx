The Transform Agent (v4) enables AI-assisted transformation workflows in Prophecy by connecting the SQL sandbox runtime to an external large language model provider. It allows the Agent to generate and reason about transformation logic using models hosted outside the Prophecy cluster.

In self-hosted environments, enabling the Transform agent requires configuration in both the Prophecy Admin UI and the Kubernetes environment that runs the SQL sandbox. This guide explains the supported versions, prerequisites, configuration steps, and validation checks required to enable the agent.

<Callout icon="/images/icon.png" color="#FFC107">
  Applicable to the [Enterprise Edition](/data-analysis/administration/platform/editions) only.
</Callout>

## Version requirements

### Supported versions

The Transform agent (v4) is supported only in Prophecy 4.2.5.3 and later.

Earlier versions (4.2.5.2 and below) do not expose the configuration options required to enable the agent.

Verify your version before continuing.

## Prerequisites

Ensure the following requirements are met before enabling the Transform agent:

- Prophecy 4.2.5.3 or later.
- Cluster admin access to the Prophecy UI.
- Kubernetes access using `kubectl`.
- Copilot already enabled.
- Access to an Anthropic API key. Supported model: claude-opus-4-5
- Knowledge Graph services deployed if lineage features are required.

## Architecture overview

the Transform agent relies on several internal services and an external LLM provider.
```

Prophecy UI
│
▼
SQL Sandbox
│
▼
External LLM provider (Anthropic)
│
▼
Optional: Knowledge Graph service

```
Key dependencies include:

- SQL sandbox runtime.
- Outbound internet access.
- Anthropic API access.
- Optional Knowledge Graph services.


<Steps>
<Step title="Configure LLM credentials in the UI">

Configure the Anthropic API key used by the Transform agent in the Prophecy UI.

1. Navigate to **Settings → Admin → Copilot Settings**.
2. Open **Available AI Models**.
3. Add the following configuration.

```json
{
  "transform_agent": {
    "anthropic_key": "YOUR_ANTHROPIC_API_KEY"
  }
}
```

</Step>
<Step title="Update sandbox resources">

The new model requires increased memory resources for the SQL sandbox.

1. Navigate to Settings > Admin > Config.
1. Scroll to the Sandbox Config section.
1. Update the SQL Sandbox Memory settings to the following values:
    - Requests: 3GB
    - Limit: 4GB

</Step>
<Step title="Configure SQL sandbox runtime">

Create or update the SQL sandbox configuration ConfigMap.

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: sql-sandbox-config-map
  namespace: <namespace>
data:
  ANTHROPIC_API_KEY: <ANTHROPIC_API_KEY>
  CLAUDE_MODEL: claude-opus-4-5
  KNOWLEDGE_GRAPH_BASE_URL: http://knowledge-graph-service.<namespace>.svc.cluster.local:50055
```

This configuration defines the following runtime settings:

- `ANTHROPIC_API_KEY` authenticates requests to Anthropic.
- `CLAUDE_MODEL` specifies the Claude model used by the SQL sandbox.
- `KNOWLEDGE_GRAPH_BASE_URL` defines the internal endpoint used for Knowledge Graph queries.

After creating the ConfigMap, update the **athena StatefulSet** to reference it.

```
SANDBOX_ENV_CM=sql-sandbox-config-map
```

Saving this configuration restarts the SQL sandbox environment so the variables are loaded.

</Step>
<Step title="Configure network policy">

The SQL sandbox must be able to call external LLM APIs.

If your Kubernetes cluster restricts outbound traffic, add an egress policy that allows internet access for SQL sandbox pods.

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
...
```

Replace the following placeholders with values appropriate for your cluster:

- `<namespace>`
- `<nodes CIDR>`
- `<service CIDR>`

</Step>
<Step title="Restart services">

Restart Prophecy services to apply the SQL sandbox configuration:

```bash
kubectl rollout restart deploy edweb-prophecy -n <namespace>
```

</Step>

<Step title="Verify the configuration">

**Verify SQL sandbox connectivity**

- Enter a SQL sandbox pod and test external connectivity.

```bash
curl https://api.anthropic.com -I
```

Expected result:

```
HTTP 200
```

or

```
HTTP 401
```

- Either response confirms network connectivity to the Anthropic API.

**Verify SQL sandbox configuration**

- Confirm the ConfigMap contains the expected variables.

```bash
kubectl get configmap sql-sandbox-config-map -n <namespace> -o yaml
```

- Verify the following fields appear in the output:

    - `ANTHROPIC_API_KEY`
    - `CLAUDE_MODEL`
    - `KNOWLEDGE_GRAPH_BASE_URL`
</Step>
</Steps>

## Troubleshooting

### Transform agent option not visible

Cause:

Prophecy version earlier than 4.2.5.3.

Solution:

Upgrade Prophecy to version 4.2.5.3 or later.

### Agent fails to run

Possible causes include the following.

| Cause                     | Symptom                     |
| ------------------------- | --------------------------- |
| Invalid Anthropic API key | Authentication errors       |
| Network egress blocked    | Request timeouts            |
| ConfigMap not applied     | Model configuration missing |

### Collect logs for debugging

If the issue persists, collect the following logs:

- SQL sandbox logs.
- edweb logs.
- orchestrator logs.

Provide these logs when contacting support.

## Preflight checklist

Before enabling the Transform agent, confirm the following:

- Prophecy version is 4.2.5.3 or later.
- Anthropic API key is configured in the Admin UI.
- SQL sandbox has outbound internet access.
- The `sql-sandbox-config-map` ConfigMap is applied to the athena StatefulSet.
