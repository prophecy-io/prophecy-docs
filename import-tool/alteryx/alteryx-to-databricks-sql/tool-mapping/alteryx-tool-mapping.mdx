## In-Database

The following table lists mappings for Alteryx [In-Database tools](https://help.alteryx.com/current/en/designer/tools/in-database.html).

For the most part, Import processes Alteryx In-Database tools in the same way it processes their standard (non–In-Database) equivalents. For example, when you import a workflow that uses a Filter In-DB tool, Import converts it to a standard Filter gem. In this case, the filtering logic is preserved, but execution does not remain tied to the original database.

More broadly, Prophecy’s [_fabrics_](/data-analysis/environment/fabrics/prophecy-fabrics) provide functionality analogous to Alteryx’s In-Database tools for fabric-supported platforms such as Databricks. When a pipeline runs on a Databricks fabric, transformations execute directly within the Databricks SQL engine, rather than in an external runtime. This is similar in spirit to how Alteryx In-Database tools push execution into the connected database.

Unlike Alteryx, however, Prophecy does not attempt to preserve database-native execution for all source systems. In-Database–style execution is preserved only when the target platform is supported as a Prophecy fabric. Users who rely on In-Database tools and want equivalent execution behavior in Prophecy must therefore run their pipelines on a supported fabric, such as Databricks.
