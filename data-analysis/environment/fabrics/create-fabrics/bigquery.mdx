To create a fabric using Google BigQuery as the provider, follow the steps below.

<Steps>
<Step title="Create a new fabric entity">
Begin by creating a new fabric entity in Prophecy.

1. From the left sidebar, click the **+** sign.
1. On the Create Entity page, select **Fabric**.

</Step>

<Step title="Fill in the Basic Info tab">
The **Basic Info** tab lets you define the key identifiers of the fabric.

1. Provide a name for the fabric.
1. (Optional) Provide a description for the fabric.
1. Select a [team](/data-analysis/administration/management/teams/teams) that can access the fabric.
1. Click **Continue**.

</Step>

<Step title="Select the provider">

The **Providers** tab allows you to choose a SQL warehouse provider. You cannot change the fabric provider after you create the fabric.

1. Under **Provider**, select **BigQuery**.

</Step>
<Step title="Fill in the Connections tab">

The **Connections** tab allows you to store your credentials to various external data providers for reuse while attached to the fabric.

- Under **SQL Warehouse Connection**, click **+ Connect SQL Warehouse**.
- Select **BigQuery** as the connection type and configure the [connection details](/data-analysis/environment/connections/bigquery).

<Info>
  You can add [Data Ingress/Egress Connections](/data-analysis/environment/connections/connections)
  to your fabric if you want, but these are not required.
</Info>

</Step>

<Step title="Save the fabric">Click **Complete** to save the fabric.</Step>

</Steps>

## Column naming limitations for Big Query fabrics

BigQuery only allows letters, numbers, and underscores in column names. When a Prophecy pipeline creates an interim table on a BigQuery fabric, special characters (such as brackets) in column names are silently converted to underscores (`_`).

This conversion happens automatically, with no warning or indication in the pipeline. Converted column names propagate downstream, and will appear in the schema for any gem connected after the interim table, including the final target gem, even if the target system (such as HANA) supports the original characters.

<Warning>
If your source data contains column names with brackets or other special characters, and your pipeline uses a BigQuery fabric for interim processing, those characters will be replaced with underscores in the interim table and in all downstream schemas, regardless of whether your final target supports the original naming.

If your final target supports special characters in column names but your pipeline runs through a BigQuery fabric, avoid relying on those characters being preserved end-to-end. We recommend either 1) renaming source columns to use only letters, numbers, and underscores before processing, or 2) accounting for renamed columns in downstream logic.
</Warning>
