For Simplified PySpark projects, you can use either Prophecy secrets or Databricks secrets to store sensitive values. This page describes how to leverage Databricks secrets in Prophecy.

<Note>
  Databricks secret support in Prophecy is currently in private preview. Some manual steps are
  required, and the experience will continue to improve in future releases.
</Note>

## Prophecy secrets

Prophecy secrets are stored actually in Databricks secrets to make it compatible as a packaged project in Databricks for execution.

When you export a Prophecy pipeline to run as a Databricks job, the system generates a `connections.yaml` file as part of the export.

In this file, any references to Prophecy secrets are substituted with placeholder entries for Databricks secrets.

To execute your exported pipeline successfully, create these secrets in your Databricks workspace. The names in your Databricks secret scope must match the names referenced in connections.yaml.

You may also directly update the secret names in the YAML file to match existing secrets in Databricks.

```
# Example connections.yaml
tableau_token: databricks://my-scope/my-token
```

In this example, you need to create a secret named my-token within the Databricks scope `my-scope`.

## Limitations

- UI support: Managing Databricks secrets from within the Prophecy UI is not supported in this release. All secret creation and editing must be done in the Databricks workspace.
- Runtime: These secrets are only referenced during execution on Databricks, not within Prophecy's managed runtimes.
- Manual setup instructions: Open the `connections.yaml` file generated by Prophecy after export. Review the keys and secret names referenced (e.g., `my-token` in `databricks://my-scope/my-token`). In the Databricks workspace, create each required secret in the designated scope. See Databricks documentation for managing secrets. (Optional) If you already have secrets with different names, update the relevant entries in `connections.yaml` accordingly.
