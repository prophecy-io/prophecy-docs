This page describes how to configure PostgreSQL Source and Target gems, including connection setup, schema options, and available write modes. Use the Postgres Source or Target gem to read from or write to a PostgreSQL database within your pipeline.

## Create a Postgres gem

To create a Postgres Source or Target gem in your pipeline:

<Steps>
<Step title="Add a Source or Target gem to the pipeline">

1. Open your pipeline in the [Studio](/data-analysis/development/studio/studio).
1. Click on **Source/Target** in the canvas.
1. Select **Source** or **Target** from the dropdown.
1. Click on the gem to open the configuration.

</Step>

<Step title="Select Postgres format">
  In the **Type** tab, select **Postgres**. Then, click **Next**.
</Step>

<Step title="Set location details">

In the **Location** tab, set your connection details and table location. To learn more, jump to [Source location](#source-location) and [Target location](#target-location).

</Step>

<Step title="Set table properties">
  In the **Properties** tab, set the table properties. To learn more, jump to [Source properties](#source-properties) and [Target properties](#target-properties).
</Step>

<Step title="Preview data (Source only)">
  In the **Preview** tab, load a sample of the data and verify that it looks correct.
</Step>

</Steps>

## Source configuration

Use these settings to configure a Postgres Source gem for reading data.

### Source location

| Parameter                   | Description |
| --------------------------- | ----------- |
| Format type                 | Table format for the source. For PostgreSQL tables, set to `postgres`. |
| Select or create connection | Select or create a new [Postgres connection](/data-analysis/environment/connections/postgres) in the Prophecy fabric you will use. |
| Schema                      | Schema containing the table you want to read from. |
| Name                        | Exact name of the PostgreSQL table to read data from. |
| Query                       | SQL query to read data from. If provided, this takes precedence over the schema and table name fields. |

### Source properties

Infer or manually configure the schema of your Source gem. Optionally, add a description for your table. Additional properties are not supported at this time.

## Target configuration

Use these settings to configure a Postgres Target gem for writing data.

### Target location

| Parameter                   | Description |
| --------------------------- | ----------- |
| Format type                 | Table format for the target. For PostgreSQL tables, set to `postgres`. |
| Select or create connection | Select or create a new [Postgres connection](/data-analysis/environment/connections/postgres) in the Prophecy fabric you will use. |
| Schema                      | Schema where the target table resides or will be created. |
| Name                        | Name of the PostgreSQL table to write data to. Whether Prophecy creates the table when it doesn't exist depends on the [write mode](#write-options). |

### Target properties

| Property    | Description                                                                                          | Default |
| ----------- | ---------------------------------------------------------------------------------------------------- | ------- |
| Description | Description of the table.                                                                            | None    |

### Write options

On the **Write Options** tab, choose how Prophecy writes data to the target table.

| Mode | Description |
| ---- | ----------- |
| Wipe & Replace Table (default) | Drops the table and creates it again with the incoming data. Requires permission to drop and create tables. |
| Truncate & Insert | Removes all rows from the existing table, then inserts the incoming data. The table must already exist. |
| Write Fresh Table; Error if Exists | Creates the table with the incoming data. Fails if the table already exists. |
| Append Rows | Inserts the incoming rows without changing existing rows. Creates the table if it doesn't exist. |
| Merge - Upsert Row | Updates rows whose key matches an incoming row and inserts the rest. See [Merge - Upsert Row](#upsert-row-merge). |
| Merge - SCD 2 | Keeps a history of changes by closing the current version of a changed row and inserting a new version. See [Merge - SCD 2](#scd-2-merge). |

Merge modes require PostgreSQL 15 or later. Prophecy loads the incoming data into a temporary staging table and runs the merge in a single transaction, so if any step fails, the target table doesn't change. If the incoming data has no rows, Prophecy doesn't write anything.

#### Upsert Row merge

The target table must already exist. Configure the following:

| Parameter | Description |
| --------- | ----------- |
| Unique Key | One or more columns that identify a row. Required. Null values in a key column match other null values. |
| Use Predicate | Additional conditions that a target row must meet to match an incoming row. |
| Use a condition to filter data for incremental runs | A condition on the incoming data. Only incoming rows that meet it are merged. |
| How to handle target rows not present in source? | What to do with target rows that have no matching incoming row: **Do nothing** (default), **Delete rows**, or **Update columns**. You can limit the action with a **Run only when** condition. Requires PostgreSQL 17 or later. |
| Merge Columns | On the **Merge Columns** tab, choose **Specify columns to merge** or **Specify columns to exclude** to limit which columns are updated when a key matches. New rows always include every column. By default, all columns are updated. |
| On Schema Change | On the **Advanced** tab, choose what happens when the incoming columns differ from the table's columns: `ignore` (default), `fail`, `append_new_columns`, or `sync_all_columns`. `sync_all_columns` also drops table columns that aren't in the incoming data, which deletes their data. |

If more than one incoming row has the same key, the merge fails. Remove duplicate keys before the Target gem.

<Warning>
If you choose **Delete rows** without a **Run only when** condition while you also filter for incremental runs, Prophecy can delete most of the table, because rows outside the incremental filter have no match.
</Warning>

#### SCD 2 merge

Prophecy creates the table if it doesn't exist and adds three tracking columns: `postgres__start_date`, `postgres__end_date`, and `postgres__is_active`. Configure the following:

| Parameter | Description |
| --------- | ----------- |
| Unique Key | One or more columns that identify a record. |
| Invalidate deleted rows | Whether to close the current version of records whose key no longer appears in the incoming data. |
| Determine new records by checking timestamp column | Detects changes with the **Updated at** column. A newer value means the record changed. This is the default. |
| Determine new records by looking for differences in column values | Detects changes by comparing the columns you select. If you don't select any, Prophecy compares all columns except the key. |

When a record changes, Prophecy sets `postgres__end_date` and sets `postgres__is_active` to `false` on the current version, then inserts a new version with `postgres__is_active` set to `true`.

## Configure a Postgres connection

Use these settings to create a Postgres connection:

| Parameter | Description |
| --------- | ----------- |
| Connection Name | Name for the connection. |
| Server | PostgreSQL server hostname or IP address. |
| Port | Port used to connect to the PostgreSQL server. |
| Database | PostgreSQL database name. |
| Username | Username used for pipeline development and scheduled execution. |
| Password | Password used for pipeline development and scheduled execution. |
| Knowledge Graph Indexer | Choose whether to enable the Knowledge Graph Indexer for this connection. |
