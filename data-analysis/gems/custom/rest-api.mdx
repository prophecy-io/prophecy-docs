## Overview

Use the RestAPI gem to make HTTP requests to external REST APIs from your pipeline. You can retrieve data, send data to downstream systems, or trigger external services as part of your workflow.

## Use cases

Common uses for the RestAPI gem include:

- Enriching pipeline data with information from an external service.
- Sending pipeline results to another application.
- Triggering external workflows or notifications.
- Retrieving reference or lookup data during pipeline execution.

## Input and output

The RestAPI gem uses the following input and output ports.

| Port | Description |
|-------|-------------|
| **in0** | (Optional) Input table. If connected, Prophecy makes one API request for each input row. |
| **out** | Output table containing the API response, along with the input columns when applicable. |

By default, the RestAPI gem does not include an input port. You can add one by clicking the **+** button next to **Ports**, or by connecting another gem directly to the RestAPI gem.

<Info>
The number of input and output ports can be changed as needed. To learn more, see [Gem ports](/data-analysis/gems/gems#gem-ports).
</Info>

## Configure the RestAPI gem

The RestAPI gem guides you through configuration using a multi-step configuration flow.

<Steps>

<Step title="Request">

The **Request** page defines the HTTP request that will be sent.

Configure the following settings.

| Setting | Description |
|---------|-------------|
| HTTP Method | Select the HTTP method to use. Supported methods include `GET`, `POST`, `PUT`, `PATCH`, `DELETE`, and `HEAD`. |
| Target URL | Enter the endpoint to call. |
| Request Body | For methods that send a request body, choose the body format and provide the request payload. Supported formats include JSON, XML, and plain text. |

You can reference input columns anywhere the gem accepts text by enclosing the column name in double curly braces.

For example:

```text
https://api.company.com/customers/{{CustomerID}}
```

You can also reference columns inside a request body.

```json
{
  "customerId": "{{CustomerID}}",
  "region": "{{Region}}"
}
```

Click **Continue** to proceed.

</Step>

<Step title="Authentication and headers">

The **Auth & Headers** page configures authentication and additional request metadata.

Choose one of the supported authentication methods:

- None
- Basic Auth
- Bearer Token
- API Key
- OAuth 2.0

You can also configure:

- **Request parameters** to append query parameters to the URL.
- **Request headers** to send additional HTTP headers.

Click **Continue** to proceed.

</Step>

<Step title="Response">

The **Response** page controls how Prophecy processes the API response.

Choose one of the following response formats:

- None
- JSON
- XML

If you select **JSON** or **XML**, you can configure response parsing.

Available options include:

- Waiting for asynchronous responses.
- Specifying a JSONPath or XPath expression used to evaluate the response.
- Choosing how often Prophecy checks for completion.
- Setting the maximum number of polling attempts.
- Testing the parsing configuration before saving.

Click **Continue** to proceed.
</Step>

<Step title="Resilience">

The **Resilience** page lets you configure retry behavior for failed requests.

Enable **Retry if the API fails** to automatically retry unsuccessful requests.

When retries are enabled, configure:

- **Retry attempts** — Maximum number of retry attempts.
- **Retry delay** — Number of seconds to wait between attempts.

Click **Save Configuration** to finish configuring the gem.

</Step>
</Steps>

## Additional considerations

- If the RestAPI gem has an input table, Prophecy sends one request for each input row.
- You can use dynamic values by referencing input columns with `{{column_name}}`.
- Authentication credentials should be stored using Prophecy secrets whenever possible.
