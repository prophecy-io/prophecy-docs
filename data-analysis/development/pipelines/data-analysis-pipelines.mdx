Pipelines are visual data preparation workflows that define how data is transformed inside a project. Pipelines provide structure and repeatability for data preparation. Pipelines move through development, production, and reporting stages within the project lifecycle.

In Prophecy's **Data Prep and Analysis** model:

- **Pipelines** handle data preparation.
- **Analyses** handle exploration, visualization, and interpretation.

A pipeline represents a connected sequence of transformations (gems) that compile to warehouse-native SQL. Pipelines produce structured, reliable datasets that analyses can use. See [Data analysis gems](/data-analysis/gems/gems) for more information on gems.

![Pipeline example](/data-analysis/development/pipelines/img/pipeline.png)

Instead of writing isolated SQL queries, you define a transformation graph that:

- Encodes business logic in a visual workflow.
- Can be iteratively refined.
- Produces consistent, reusable outputs.
- Can be versioned.

Because pipelines compile to SQL, all execution happens in your warehouse under your existing credentials and access controls.

## Data prep and analysis

Analytical workflows are divided into two layers:

### Data preparation (Pipelines)

Pipelines define:

- How source data is cleaned and transformed.
- How datasets are joined and reshaped.
- How outputs are produced for downstream use.

Each transformation is part of a visual graph and compiles to SQL that runs in your connected warehouse.

### Analysis and visualization (Analyses)

[Analyses](/data-analysis/production/analysis/overview) are created within pipelines and focus on:

- Exploring prepared datasets.
- Creating visualizations.
- Interpreting results.

Analyses can trigger pipeline execution but do not replace the underlying transformation workflow.

## Building a pipeline

### Using the Transform Agent

The Transform Agent can generate or modify pipelines using natural language.

When using the Agent, you:

- Describe the transformation you want.
- Review generated gems and connections.
- Inspect compiled SQL.
- Validate results before finalizing changes.

The Agent accelerates development, but all transformations remain visible and editable.

### Building visually on the canvas

You can also create a pipeline from the project browswer by clicking **+** to the right of **Pipelines**.

When creating a pipeline, you provide:

- **Pipeline name** — A unique name within the project.
- **Directory path** — The location where the pipeline is stored in the project.

## Modifying pipelines

Once you have created a pipeline, you can:

- Drag gems onto the canvas.
- Connect transformations to define data flow.
- Preview result using the [Data Explorer](/data-analysis/development/runs/data-explorer/data-explorer).
- Configure transformation logic.
- Inspect the compiled SQL.
- Run the pipeline to validate outputs.

Each gem represents a transformation step. Connected gems form a complete data workflow.

## Execution and validation

Pipelines can be run interactively, scheduled for production, or triggered through analyses.

When you run a pipeline:

- The visual graph compiles to SQL.
- Queries execute in your connected warehouse.
- Execution respects your existing permissions.
- Output datasets are updated based on the defined transformations.

You can re-run pipelines to validate changes or refresh prepared datasets before analysis. You can also run individual transformation steps to validate intermediate outputs.

## Project structure

Pipelines appear in the project browser alongside other project artifacts.

Within each pipeline:

- Transformation logic is defined on the canvas.
- Analyses are nested under the pipeline.
- Outputs can be referenced by downstream workflows.

Pipelines provide organizational boundaries inside a project. You can create separate pipelines to isolate domains, workflows, or business processes.

## Human in the loop

Whether built manually or generated by the Agent, pipelines remain under your control.

You can:

- Inspect every transformation.
- Modify generated logic.
- Validate schema changes.
- Re-run transformations as needed.

You are responsible for validating data correctness and ensuring that prepared datasets are suitable for analysis.
