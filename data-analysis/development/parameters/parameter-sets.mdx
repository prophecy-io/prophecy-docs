Parameter sets group related variables together, allowing you to switch between different configurations for environments, regions, tenants, or other scenarios. You can create parameter sets at the project level or the pipeline level.

## What are parameters?

In Prophecy, a parameter is a placeholder for information that might change, such as a date, a country name, or a database location. Instead of typing the same value over and over, you use a parameter. You reference these parameters in your pipeline as [configuration variables](/data-analysis/development/parameters/usage).

There are two types of parameters: project parameters and pipeline parameters. The following table summarizes the key differences between them:

| Parameter type      | Description                                                                                                                                                                                                                                    |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Project parameters  | Shared across all pipelines in a project.<br/><br/>String expressions remain as literal strings. If you define a project parameter as `concat("first_name", "last_name")`, its usage remains as `concat("first_name", "last_name")`.<br/><br/> |
| Pipeline parameters | Specific to a single pipeline.<br/><br/>String expressions are evaluated at runtime. If you define a pipeline parameter called `concat("first_name", "last_name")`, the value injected during usage is `first_namelast_name`.<br/><br/>        |

<Note>
  If a pipeline parameter and a project parameter share the same name, the pipeline parameter takes
  precedence within that pipeline.
</Note>

<Info>The difference in evaluation behavior will be resolved in a future release.</Info>

## What are parameter sets?

Parameter sets let you define groups of variables. Each set contains values for multiple parameters, and you can activate one set at a time. This is useful for:

- Environment-specific configurations (dev, staging, prod)
- Multi-tenant or client-specific settings
- Regional or compliance variations
- Currency and locale transformations

### Default parameter set

Every project has a `default` parameter set. Variables defined in the default set serve as fallback values when other sets don't specify a value. You can mark other parameter sets as active to override default values.

### Inheritance

When a parameter set doesn't define a value for a variable, it inherits from the default set. In the interface, inherited values display as "Inherited" rather than showing an explicit value.

### Active parameter set

When you create or edit parameter sets, you can select one to be the **active** parameter set. The active parameter set is the one that is used when you run a pipeline interactively during development. It is **not** the parameter set used for scheduled pipeline runs or Prophecy App runs; you select the parameter set for those cases separately.

## Create parameter sets

To create a new parameter set, you first need to define the variables in the **default** parameter set.

1. Open **Parameters** from the project header.
2. Select either **Project Parameters** or **Pipeline Parameters**.
3. Add variables to the set by clicking **+ Add Variable**.
4. Enter values for each variable, or leave them empty to inherit from the default set.
5. Click **Save**.

<Note>By default, the default set is active</Note>

To add and activate a new parameter set, you need to:

1. Open **Parameters** from the project header.
2. Click **+ Add Parameter Set**.
3. Enter a name for the parameter set.
4. Assign values to the variables or leave them empty to inherit the default.
5. Toggle **Active** to make this set the active configuration.
6. Click **Save**.

## Select parameter sets

After you define your parameter sets, you must select which set to apply when running your pipeline. Choosing a set determines which values Prophecy uses during execution.

### Scheduling

When you [schedule](/data-analysis/production/scheduling/scheduling) a pipeline, you can choose which pipeline-level parameter set to use for that schedule. This lets you run the same pipeline with different configurations on different schedules.

To select a pipeline parameter set when scheduling:

1. Open the pipeline and navigate to **Scheduling**.
2. Create a new schedule or edit an existing one.
3. In the schedule configuration, find the **Choose Pipeline Parameter Set** dropdown.
4. Select the parameter set you want to use for this schedule.
5. Configure other schedule settings, such as frequency and time.
6. Save the schedule.

<Note>
  Because a schedule only controls a single pipeline, you can only select pipeline parameter sets
  here. The project parameter set will be determined when you publish the project.
</Note>

### Publishing

When you [publish](/data-analysis/production/publication) a project, you can choose which project-level parameter set to use. This allows you to publish different configurations to different environments without modifying the project.

To select a project parameter set when publishing:

1. Open the project and click **Publish**.
2. In the **Version details** dialog, find the **Choose Project Parameter Set** dropdown.
3. Select the parameter set you want to use for this publication.
4. Complete the publication process.

The selected project parameter set applies to all deployed pipelines in the published project. Pipeline parameter sets selected for schedules also apply to those scheduled runs. If a pipeline parameter and a project parameter share the same name, the pipeline parameter value takes precedence.

### Running Prophecy Apps

You can select a parameter set when creating a Prophecy App or modify it afterward in app settings. This determines which parameter values the app uses when it runs.

To select a parameter set when creating an app:

1. Click **+ Add Entity** and select **App**.
2. In the **Create App** dialog, find the **Parameter Set** dropdown.
3. Select the parameter set you want to use for this app.
4. Complete the app creation process.

To change the parameter set for an existing app:

1. Open the app.
2. Click the settings icon or open **App Settings**.
3. Find the **Choose Parameter Set** dropdown.
4. Select the parameter set you want to use.
5. Click **Save**.

The selected parameter set applies to all app runs by default unless the end user provides their own values.

<Note>

Each Prophecy App runs a single pipeline, which can use both project parameters and pipeline parameters. When configuring an app, you select a pipeline parameter set to control the pipeline parameters. Project parameters are handled separately:

- For interactive app runs, project parameters use the active project parameter set.
- For scheduled app runs, project parameters use the project parameter set selected when you published the project.

</Note>

## Example

This example demonstrates how to use parameter sets to process sales data for different global regions.

When you switch regions, you often need to change more than one piece of information at a time. In this scenario, we use two parameters that must stay in sync:

- `currency`: Labels the final report (for example, **USD** or **EUR**).
- `fx_rate_table`: Tells the pipeline which database table contains the specific exchange rates for that region.

By grouping these into parameter sets, you ensure that when you switch sets, pipelines use both the correct label and the correct exchange rates.

### 1. Define the default values (USA)

First, set up your standard operating values in the default set:

1. Open **Parameters** in the project header and select **Project Parameters**.
1. Click **+ Add Variable** and name it `currency`.
1. Set the value to `USD`.
1. Click **+ Add Variable** again and name it `fx_rate_table`.
1. Set the value to `fx_rates_usd`.
1. Click **Save**.

After saving the set of variables, you can reference `currency` and `fx_rate_table` in any pipeline in the project. Your pipeline will use the default set values by default for interactive runs.

### 2. Create a regional override (Europe)

Next, create a set for your European operations:

1. Click **+ Add Parameter Set** and name it `Europe`.
1. In the `Europe` set, change the value of `currency` to `EUR`.
1. Set the value of `fx_rate_table` to `fx_rates_eur`.
1. Toggle **Active** to make this set the active configuration.
1. Click **Save**.

By switching the active set to `Europe`, you update your entire project to handle European data without manually changing every pipeline component.
