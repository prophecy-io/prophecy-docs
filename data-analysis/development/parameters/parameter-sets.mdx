Parameter sets group related variables together, allowing you to switch between different configurations for environments, regions, tenants, or other scenarios. You can create parameter sets at the project level or the pipeline level.

## Project parameters vs pipeline parameters

Project parameters are shared across all pipelines in a project. Pipeline parameters are specific to a single pipeline.

### Evaluation behavior

The key difference between project and pipeline parameters is how string expressions are evaluated:

- **Pipeline parameters**: String expressions are evaluated at runtime. If you define a pipeline parameter called `concat("first_name", "last_name")`, the value injected during usage is `first_namelast_name`.
- **Project parameters**: String expressions remain as literal strings. If you define a project parameter as `concat("first_name", "last_name")`, its usage remains as `concat("first_name", "last_name")`.

This discrepancy will be resolved in a future release.

<Info>
  If a pipeline parameter and a project parameter share the same name, the pipeline parameter takes
  precedence within that pipeline.
</Info>

## Parameter sets

Parameter sets let you define multiple configurations for the same variables. Each set contains values for your parameters, and you can activate one set at a time. This is useful for:

- Environment-specific configurations (dev, staging, prod)
- Multi-tenant or client-specific settings
- Regional or compliance variations
- Currency and locale transformations

### Default parameter set

Every project has a `default` parameter set. Variables defined in the default set serve as fallback values when other sets don't specify a value. You can mark other parameter sets as active to override default values.

### Inheritance

When a parameter set doesn't define a value for a variable, it inherits from the default set. In the interface, inherited values display as "Inherited" rather than showing an explicit value.

## Create parameter sets

To create a new parameter set:

1. Open **Parameters** in the project header.
2. Select either **Project Parameters** or **Pipeline Parameters**.
3. Click **+ Add Parameter Set**.
4. Enter a name for the parameter set.
5. Add variables to the set by clicking **+ Add Variable**.
6. Enter values for each variable, or leave them empty to inherit from the default set.
7. Toggle **Active** to make this set the active configuration.
8. Click **Save**.

## Select parameter sets

### Project-level

When you publish a project, you can choose which project-level parameter set to use. This allows you to publish different configurations for different environments or use cases without modifying the project code.

#### Publishing

To select a project parameter set when publishing:

1. Open the project and click **Publish**.
2. In the **Version details** dialog, find the **Choose Project Parameter Set** dropdown.
3. Select the parameter set you want to use for this publication.
4. Complete the publication process.

The selected project parameter set applies to all deployed pipelines.

### Pipeline-level

When you schedule a pipeline, you can choose which pipeline-level parameter set to use for that schedule. This lets you run the same pipeline with different configurations on different schedules.

#### Scheduling

To select a pipeline parameter set when scheduling:

1. Open the pipeline and navigate to **Scheduling**.
2. Create a new schedule or edit an existing one.
3. In the schedule configuration, find the **Choose Pipeline Parameter Set** dropdown.
4. Select the parameter set you want to use for this schedule.
5. Configure other schedule settings such as frequency and time.
6. Save the schedule.

Each schedule can use a different pipeline parameter set, allowing you to run the same pipeline with different configurations at different times.

#### Prophecy Apps

You can select a parameter set when creating a Prophecy App or modify it afterward in app settings. This determines which parameter values the app uses when it runs.

To select a parameter set when creating an app:

1. Click **+ Add Entity** and select **App**.
2. In the **Create App** dialog, find the **Parameter Set** dropdown.
3. Select the parameter set you want to use for this app.
4. Complete the app creation process.

To change the parameter set for an existing app:

1. Open the app.
2. Click the settings icon or open **App Settings**.
3. Find the **Choose Parameter Set** dropdown.
4. Select the parameter set you want to use.
5. Click **Save**.

The selected parameter set applies to all app runs until you change it in app settings.

## Currency example

This example demonstrates using parameter sets to handle currency conversions across different regions.

### Create project parameters

1. Open **Parameters** in the project header.
2. Select **Project Parameters**.
3. In the `default` parameter set, add a variable named `currency` with value `USD`.
4. Add a variable named `fx_rate_table` with value `fx_rates_usd`.
5. Click **+ Add Parameter Set** and name it `EUR`.
6. In the `EUR` set, add `currency` with value `EUR`.
7. Add `fx_rate_table` with value `fx_rates_eur`.
8. Toggle **Active** on the `EUR` set.
9. Click **Save**.

### Use in pipelines

Reference these project parameters in your pipelines using configuration variables. The active parameter set determines which values are used:

- When `EUR` is active, `currency` resolves to `EUR` and `fx_rate_table` resolves to `fx_rates_eur`.
- When `default` is active, `currency` resolves to `USD` and `fx_rate_table` resolves to `fx_rates_usd`.
